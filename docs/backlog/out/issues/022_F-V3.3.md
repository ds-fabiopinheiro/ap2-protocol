## Problema
O Processor Agent não está publicado e os agentes A2A do cenário human-present usam o modelo gemini-3.1-flash-lite-preview fixo no código (common/function_call_resolver.py).

## Solução proposta
Subir o Processor Agent na porta 8003, só interna, e fazer os agentes A2A lerem o modelo de AGENT_MODEL, com a mesma regra da v2 (LiteLLM quando houver prefixo de provedor).

## Usuários impactados
Responsável pela homologação (troca de modelo sem alterar código).

## Regras de negócio
- RN01 – A porta 8003 não é exposta pelo nginx.
- RN02 – Sem AGENT_MODEL, o modelo padrão continua gemini-3.1-flash-lite-preview.

## Fora de escopo
- Exposição pública do Processor Agent.

## Dependências
- F-V3.1 concluída.

## Critérios de aceite
- [ ] O Processor Agent responde em 127.0.0.1:8003 dentro do container.
- [ ] Uma requisição externa para /a2a/merchant_payment_processor_agent recebe 404.
- [ ] Com AGENT_MODEL alterado, o log dos agentes A2A mostra o novo modelo.

- F-V3.3.1 · Merchant Payment Processor Agent em execução interna com desafio OTP
- F-V3.3.2 · Modelo dos agentes A2A definido por AGENT_MODEL
