## Contexto
O repositório tem dois exemplos fora do Python: code/samples/go (Merchant, Credentials Provider e Processor em Go para o cenário human-present/cards, com o Shopping Agent Python) e code/samples/android (app Android de compras com Digital Payment Credentials, que usa Merchant e Credentials Provider Python nas portas 8001/8002 via `adb reverse`). O app lê GEMINI_API_KEY do local.properties e grava a chave no BuildConfig, e usa URLs http://localhost fixas.

## Objetivo
Permitir validar o cenário assistido com backend em Go e distribuir um APK de homologação que usa o backend público.

## Escopo incluído
- Branch homolog-v6 e Space ap2-homolog-v6.
- Build e execução dos agentes Go no container, com seleção Python × Go.
- App Android com URL do backend configurável e sem chave do Gemini no APK.
- APK de homologação publicado no GitHub Releases.

## Escopo excluído
- Publicação na Google Play.
- Versão iOS.

## Métrica de sucesso
- Compra assistida concluída com backend Go em 3 execuções seguidas.
- APK de homologação instalado em aparelho físico concluindo uma compra com DPC.

## Dependências
- Épico v5 concluído (jornada assistida).
- Aparelho Android compatível com Credential Manager/DPC para o teste.
- Certificado de demonstração do DPC (certs/ds_cert_sdjwt.pem) disponível no backend.

## Riscos
- Uma chave do Gemini dentro do APK fica exposta a qualquer pessoa que instalar o app.
- O Credentials Provider do cenário Android usa chave pública do Agent Provider extraída do certificado DPC; pode conflitar com a configuração da v4/v5.

- Os agentes Go chamam ou não o Gemini — verificar no código antes de estimar o consumo.
- O app aceita trocar as URLs em tempo de build ou na tela de configurações (SettingsScreen.kt usa constante).
