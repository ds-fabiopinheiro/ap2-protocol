## Contexto
O Shopping Agent v1 (roles/shopping_agent) é um agente coordenador com sub-agentes (shopper, shipping_address_collector, payment_method_collector) que conversa com Merchant, Credentials Provider e Processor por A2A. É o agente do cenário human-present/cards, em que o usuário confirma carrinho, endereço, forma de pagamento e OTP. No repositório ele roda com `adk web` (tela de desenvolvimento do ADK, porta 8000).

## Objetivo
Publicar o cenário human-present/cards completo na v4, com o usuário executando a compra assistida pelo ADK Web.

## Escopo incluído
- Branch homolog-v4 e Space ap2-homolog-v4.
- Credentials Provider Agent (porta 8002, interno).
- Shopping Agent v1 acessível pelo ADK Web, restrito a esse agente.
- Roteiro de compra assistida ponta a ponta.
- Registro dos mandates da jornada assistida no Supabase.

## Escopo excluído
- Tela da jornada assistida no web client React (v5).
- Agentes em Go (v6).

## Métrica de sucesso
- Compra assistida concluída pelo ADK Web em 3 execuções seguidas, com OTP 123.
- Payment Mandate assinado pelo usuário registrado em ap2_env_mandates (environment='v4').
- Pico de RPM abaixo de 15 durante uma compra assistida.

## Dependências
- Épico v3 concluído (Merchant e Processor Agents).
- Cota do Gemini: 4 agentes com LLM por compra.

## Riscos
- O ADK Web é uma tela de desenvolvimento: lista todos os agentes do diretório e expõe a API do ADK. Precisa de diretório dedicado e limite de requisições.
- Consumo do Gemini maior que na jornada autônoma (Shopping Agent v1 e 3 agentes remotos chamam o modelo).

## Premissas
- O ADK Web funciona atrás do nginx em um subcaminho ou em porta dedicada exposta pelo nginx; a forma será definida na task de spike.
- Os endereços localhost:8001/8002 fixos em remote_agents.py continuam válidos porque todos os agentes rodam no mesmo container.
- O Shopping Agent v1 e seus sub-agentes já usam common/retrying_llm_agent.py (RetryingLlmAgent). Com o padrão max_retries=1, o código faz uma única tentativa e não repete; quando repete, repete qualquer exceção, sem espera. Precisa seguir a regra de retry da v2 (RN04 de F-V3.3.2).
